# Мультибот-платформа · LLM Memory Strategies

> Демонстрационная Streamlit-платформа, которая на одном экране показывает **четыре принципиально разных подхода** к управлению контекстом и памятью LLM: stateless, session, hybrid (FAISS) и hybrid + web-search. Все боты работают параллельно и используют один и тот же OpenAI-совместимый API провайдера **AiTunnel**.

---

## 🎯 Назначение проекта

Современные LLM «забывают» всё между запросами. Способ, которым приложение **снабжает модель контекстом**, определяет качество ответов, расход токенов и пользовательский опыт. Этот репозиторий — наглядное пособие:

| Что хочется понять | Где это видно |
|---|---|
| Что будет, если не передавать историю вообще? | **Бот №1** |
| Как влияет полная история сессии (SQLite)? | **Бот №2** |
| Что даёт долгосрочная память между сессиями? | **Бот №3** |
| Что даёт подмешивание свежих данных из интернета? | **Бот №4** |

Хронология диалога для Ботов №2–№4 хранится в **SQLite** (`history.db`),
чтобы история переживала `F5` и перезапуск приложения. Векторная база
(FAISS) используется только как слой долгосрочной семантической памяти.

Откройте четыре вкладки, напишите один и тот же вопрос в каждый чат и сравните ответы.

## 🧠 Три архитектуры памяти

### Бот №1 · Stateless (без памяти)
- В API уходит **только последнее сообщение** пользователя.
- История в UI отображается исключительно для удобства оператора.
- Модель каждый раз стартует «с чистого листа».
- **Когда уместно:** одноразовые Q&A, классификация, извлечение сущностей, перевод.

### Бот №2 · Session (контекстная память)
- В API передаётся **вся история текущей сессии** браузера.
- Историю хранит **SQLite** (`history.db` в корне проекта) — она переживает `F5` и перезапуск приложения.
- Модель «помнит» всё, что было сказано в этой вкладке.
- Память стирается кнопкой «Очистить историю сессии» или из боковой панели.
- **Когда уместно:** диалоговые ассистенты, уточняющие вопросы, отладка в режиме диалога.

### Бот №3 · Hybrid (SQLite-хронология + FAISS)
- Сочетает два слоя памяти:
  - **хронологический** — последние 10 реплик из SQLite (источник правды по порядку);
  - **семантический** — top-k релевантных фактов из FAISS-индекса.
- Эмбеддинги строятся **локально** моделью `all-MiniLM-L6-v2` (384 dim) — API-токены не тратятся.
- Хранилище FAISS персистентно на диске (`vector_store/faiss.index` + `metadata.json`).
- На каждом запросе формируется `system`-промпт с подборкой фактов из прошлых бесед.
- **Когда уместно:** персональные ассистенты, долгие проекты, техподдержка с историей обращений.

### Бот №4 · Hybrid + Web-Search (DuckDuckGo)
- Полностью наследует стратегию памяти Бота №3 (SQLite-хронология + FAISS top-k).
- Перед каждым запросом делает **свежий поиск в DuckDuckGo** через библиотеку `ddgs` (новое имя пакета, ранее `duckduckgo-search`).
- В `system`-промпт автоматически добавляется **текущая дата/время сервера** (например, «Сегодня понедельник, 5 октября 2026 года»).
- Если в запросе есть «сегодня/вчера/сейчас/...», бот подмешивает год и месяц в запрос к DuckDuckGo, чтобы сниппеты были свежими.
- Полученные сниппеты (заголовок, URL, краткое описание) добавляются в `system`-промпт как приоритетный источник фактов.
- В UI есть переключатель «🌐 Искать в интернете» и expander со списком использованных источников.
- Количество сниппетов настраивается через `WEB_SEARCH_MAX_RESULTS` в `.env` (по умолчанию 5).
- **Когда уместно:** вопросы о новостях, курсах валют, погоде, актуальных событиях — там, где знания LLM уже устарели.

## 🖥️ Интерфейс

После запуска приложение открывается на `http://localhost:8501`.

**Боковая панель:**
- Выбор модели из реестра (`MODELS` в `src/llm/models.py`).
- `Temperature` 0.0 – 2.0, шаг 0.1.
- Глобальный сброс одной из четырёх историй (3 сессии + 1 долгосрочная).

**Главная область:**
- Четыре независимые вкладки со стримингом ответов.
- У Ботов №3 и №4 — отдельные кнопки очистки FAISS-памяти и счётчики записей.
- У Бота №4 — переключатель web-поиска и expander с источниками.

## 🌱 Seed долгосрочной памяти: `seed_auto_data.py`

В корне лежит автономный CLI-скрипт, который наполняет `vector_store/`
тестовыми фактами на тему «Автомобили и автотехнологии» и сразу
проверяет работу семантического поиска.

**Что делает скрипт:**
1. Берёт 20 уникальных фраз из константы `AUTO_FACTS`
   (Tesla Autopilot, двигатель V8, замена масла, шины-липучки,
   Zeekr, LiXiang, BYD, Ferrari, Bugatti и т. д.).
2. Локально кодирует их моделью `all-MiniLM-L6-v2` (384 dim) и
   добавляет в существующий FAISS-индекс через те же хелперы
   `src.memory.vector_memory._load_index` / `_save_index`.
3. Прогоняет 3 смысловых запроса (`SEARCH_QUERIES`) через `IndexFlatIP`
   с косинусным сходством и печатает top-k: **id, score, текст**.

**Запуск (из корня проекта, в активированном `.venv`):**

```bash
# Добавить 20 фактов к уже существующему индексу (рекомендуемый режим)
python seed_auto_data.py

# Полная пересборка: очистить FAISS и metadata.json, записать только AUTO_FACTS
python seed_auto_data.py --reset
```

> 💡 Модель `all-MiniLM-L6-v2` обучена преимущественно на английском —
> на русских запросах семантика «работает», но может уступать
> специализированным мультиязычным моделям. Это ограничение самой модели,
> а не скрипта.

## ⚙️ Стек

- **Python 3.10+** (протестировано на 3.12)
- **Streamlit** — UI
- **openai ≥ 1.0** — клиент к AiTunnel (OpenAI-совместимое API)
- **FAISS-cpu + sentence-transformers** — локальные эмбеддинги и векторный поиск
- **duckduckgo-search ≥ 6.0** — web-поиск для Бота №4
- **SQLite3 (stdlib)** — хронологическая база `history.db` для Ботов №2–№4
- **python-dotenv** — конфигурация через `.env`

## 🚀 Быстрый старт (Windows)

Двойной клик по `start.bat`. Скрипт последовательно:

1. Останавливает уже запущенные `streamlit.exe`.
2. Чистит `__pycache__`, `.pytest_cache`, `.mypy_cache`.
3. Создаёт `.venv`, если его ещё нет.
4. Ставит/обновляет зависимости из `requirements.txt`.
5. Копирует `.env.example` → `.env`, если `.env` отсутствует.
6. Запускает `streamlit run app.py`.

```bat
start.bat
```

После старта **откройте `.env`** и впишите свой `AITUNNEL_API_KEY`. По умолчанию приложение слушает `http://localhost:8501`.

## 🔐 Конфигурация (`.env`)

Все параметры собраны в одном месте и читаются из `src.config`:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `AITUNNEL_API_KEY` | Ключ провайдера | — (обязательно) |
| `AITUNNEL_BASE_URL` | Базовый URL API | `https://aitunnel.ru` |
| `EMBEDDING_MODEL` | Локальная модель эмбеддингов | `all-MiniLM-L6-v2` |
| `EMBEDDING_DIM` | Размерность вектора | `384` |
| `TOP_K` | Сколько фактов подмешивать в system-промпт | `3` |
| `DEFAULT_TEMPERATURE` | Стартовое значение температуры | `0.7` |

### Принципы

- **OOP / Strategy.** Каждая стратегия памяти — самостоятельный класс с единым интерфейсом `BaseMemory.build_context()` и `BaseMemory.remember()`. Бот получает «готовое» хранилище через конструктор и не знает деталей реализации.
- **Single Responsibility.** `bots/*` — UI и сценарии, `memory/*` — хранилища, `llm/*` — интеграция с API, `ui/*` — визуальный слой, `utils/*` — общие хелперы.
- **DRY.** Общий потоковый чат-loop вынесен в `BaseBot._chat_loop()`; конкретные боты переопределяют только сценарий и `system`-промпт.
- **Масштабируемость.** Добавить нового бота = создать `src/bots/<name>_bot.py` (наследник `BaseBot`) + (опц.) новый класс памяти в `src/memory/`. Регистрация — одна строка в `build_bot_registry()`.
- **Конфигурируемость.** Никаких хардкодов в бизнес-логике: ключи, модели, размерности — в `.env` / `src.config`.

## 🩺 Диагностика

- **«⚠️ AITUNNEL_API_KEY не найден»** — не создан `.env` или ключ пустой. Скопируйте `.env.example` и впишите значение.
- **«❌ Ошибка аутентификации»** — проверьте ключ и баланс провайдера.
- **«❌ Ошибка сети»** — нет доступа к `AITUNNEL_BASE_URL` (проверьте VPN/прокси).
- **Бот №3 не «помнит»** — нажмите «Очистить долгосрочную память» и проведите новый диалог: факты появятся в `vector_store/metadata.json`.

## 📝 Лицензия и данные

- Все эмбеддинги считаются **локально** — никакие тексты не покидают машину.
- В API уходит только то, что вы отправили в чат, плюс выбранная модель и `temperature`.
- FAISS-индекс хранится на диске в `vector_store/` (исключён из git через `.gitignore`).
